# GLOSSARY.md

Comprehensive terminology, architectural concepts, and domain definitions for **OopsScam** (OopsScam).

---

## 1. Domain & Fraud Concepts

- **Smishing (SMS Phishing):** Phishing attacks delivered through Short Message Service (SMS) or instant messaging platforms (Viber, WhatsApp, Telegram, Messenger). Typically impersonates Philippine banks, e-wallets, telcos, couriers, or government agencies.
- **OTP (One-Time Password / One-Time PIN):** A dynamic authentication code sent via SMS to verify transactions or logins.
- **Real-OTP Rule:** An explicit exclusion rule in the detection engine. Legitimate transactional OTP messages frequently contain security warning keywords (e.g., *"Do not share your OTP with anyone"*). Without this rule, naive pattern matchers flag genuine bank notifications as scams.
- **Lookalike Domain (Typosquatting / Combosquatting):** A deceptive domain name crafted to resemble an authentic service (e.g., `gcash-verify.xyz` or `bpi-online-security.com` mimicking `gcash.com` and `bpi.com.ph`).
- **URL Shortener:** Link shortening services (e.g., `bit.ly`, `tinyurl.com`, `is.gd`) used by threat actors to disguise malicious or unvetted destinations in SMS.
- **APK Sideloading:** Direct links to Android package files (`.apk`) delivered in chat or SMS. These frequently install banking trojans or surveillance spyware bypassing the Google Play Store.
- **Urgency Cues / Social Engineering:** Psychological manipulation tactics that induce panic or greed (e.g., *"Account suspended within 24 hours"*, *"SIM card will be deactivated"*, *"Claim your ₱5,000 cash aid now"*).
- **Taglish:** The conversational blend of Tagalog and English prevalent in the Philippines. Used across all OopsScam explanations and actionable advice to maximize comprehension for everyday users.

## 2. Detection & Scoring Pipeline

- **Verdict:** The final categorical risk evaluation assigned to an input. Must be one of three states:
  - **Scam (High Risk):** Aggregate score $\ge 60$. Confirmed malicious patterns or high-confidence phishing indicators.
  - **Suspicious (Moderate Risk):** Aggregate score $30 \le \text{score} < 60$. Multiple cautionary signals requiring manual verification.
  - **Low Risk:** Aggregate score $< 30$. No prominent red flags detected. *(Note: The term "Safe" is strictly forbidden; no heuristic or model can guarantee complete safety.)*
- **Verdict Fusion:** The decision arbiter located in [`src/core/fusion.ts`](file:///D:/Hackathon/OopsScam/src/core/fusion.ts) that merges deterministic rule scores with probabilistic ML classifier outputs.
- **One-Way Verdict Invariant:** A core architectural guardrail stating that an LLM can **never** downgrade a verdict generated by rules and the ML classifier. It may only maintain the verdict or elevate `Low risk` to `Suspicious` if confidence $\ge 80\%$.
- **Heuristic Rule Engine:** Deterministic, regex- and logic-based checkers in [`src/core/rules.ts`](file:///D:/Hackathon/OopsScam/src/core/rules.ts) evaluating link structures, OTP requests, urgency keywords, and spoofed senders.
- **Red Flag:** A distinct, high-threat indicator that heavily drives the risk score upward (e.g., asking for an OTP via a link).
- **Informational Flag:** Contextual signals extracted to assist the user or LLM reasoning without heavily penalizing legitimate alerts.
- **Highlight Engine:** The utility in [`src/core/highlight.ts`](file:///D:/Hackathon/OopsScam/src/core/highlight.ts) mapping flagged substrings and regular expressions to exact character offsets in the input text for UI text highlighting.

## 3. On-Device AI & Machine Learning

- **Local AI / On-Device AI:** Computational inference performed entirely on the client hardware (CPU/NPU) without calling external cloud APIs, transmitting network telemetry, or requiring internet connectivity.
- **GGUF (GPT-Generated Unified Format):** The binary container format for storing quantized neural network weights used by `llama.cpp` and `llama.rn`.
- **Quantization (Q4_K_M):** 4-bit integer quantization technique balancing model accuracy and runtime memory footprint, allowing models like Qwen3 0.6B to operate under 500 MB of mobile RAM.
- **`llama.rn`:** The React Native native bridge module running `llama.cpp` locally on Android devices.
- **Small Language Model (SLM):** Sub-2B parameter language models (such as `Qwen_Qwen3-0.6B`) optimized for edge inference and specialized natural language tasks (e.g., Taglish explanation generation).
- **Prompt Injection Defense:** Treating all raw input text, OCR transcripts, and link titles as untrusted user payload wrapped within strict delimiters, preventing adversarial prompts inside messages from hijacking system instructions.
- **TF-IDF + Logistic Regression:** The lightweight machine learning classifier in [`src/ml/classifier.ts`](file:///D:/Hackathon/OopsScam/src/ml/classifier.ts) trained on character and word n-grams, scored locally in pure TypeScript against exported JSON weights (`assets/classifier.json`).

## 4. Vision & OCR (Optical Character Recognition)

- **ML Kit (Bundled Models):** Google's on-device vision library (`com.google.mlkit:text-recognition` and `com.google.mlkit:barcode-scanning`). Must be integrated as standalone, bundled binaries rather than Google Play Services dynamic dependencies to guarantee 100% offline functionality in airplane mode.
- **OCR (Optical Character Recognition):** On-device text extraction from user-provided screenshots (e.g., screenshots of Viber/SMS conversations).
- **QR Code Detector:** Barcode scanner that unpacks encoded URLs from physical or digital QR codes to feed directly into the link analysis pipeline.

---

## 5. Software Architecture & Operating Environment

- **Pure TypeScript Core:** The isolated domain engine in [`src/core/`](file:///D:/Hackathon/OopsScam/src/core/) containing zero React Native, DOM, or device dependencies. Runs natively in Node.js for ultra-fast unit testing, benchmark evaluation, and CI pipelines.
- **Zero Digital Footprint:** The absolute privacy guarantee where analyzed SMS texts, screenshots, extracted URLs, and scan histories are evaluated exclusively in-memory and discarded upon navigation or app restart. No database (such as SQLite) or local file storage retains user content.
- **Expo Development Build:** A custom native build (`npx expo run:android`) incorporating custom C++/NDK native libraries (`llama.rn`, bundled `ML Kit`), replacing the standard Expo Go sandboxed client.
- **Share Target / Android Intent:** Native Android intent filter (`expo-share-intent` or Expo linking) allowing users to forward suspicious texts or screenshots into OopsScam directly from their native SMS or messaging apps.
- **Status Strip:** UI component indicating offline operation, active on-device runtime, and engine status without network indicators.
